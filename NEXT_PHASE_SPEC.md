# Phase 2 Specification: RWG Settings Architect & `PW3-` Code Studio

## 1. Executive Summary & Context
This specification outlines the next development phase for **`sat-rwg-map`**, a local Rust/Axum web application that parses and visualizes worlds generated by the Satisfactory **RandomWorldGenerator (RWG)** mod (by *HEHE! PONIES!* / *SmallestViolin*).

The current application already decompresses Satisfactory `.sav` files, extracts procedural terrain (`PWW1`), and renders a full-screen interactive Leaflet map of resource nodes, player structures, and drop pods.

This phase adds a second core mode to the application: **The RWG World Architect & Code Studio**. It enables players to:
1. Configure all generation parameters (seed, continent layout, node clustering, purity rules, and resource multipliers).
2. Preview exact mathematical node census estimations (Iron, Copper, Coal, Oil, etc.).
3. **Export** valid, copy-pasteable **`PW3-...` settings codes** and JSON presets for Satisfactory.
4. **Import & Decode** existing `PW3-...` codes to inspect any world's settings before playing.

## 2. Technical Protocol: Reverse-Engineered `PW3-` Binary Format

Satisfactory RWG settings codes (e.g., `PW3-AxQMAwHtX4Q...`) use a compact, URL-safe Base64 binary payload with an IEEE 802.3 CRC32 checksum.

### Binary Layout
```
[ Prefix: "PW3-" ]
[ Payload: URL-Safe Base64 Decoded Bytes ]
  ├─ Byte 0:          Format Version (u8 = 3)
  ├─ Bytes 1..3:      Header Version / Compatibility (u8, u8, u8: typically 0x14, 0x0C, 0x03)
  ├─ Byte 4:          Flags (Bit 0: CodeIncludesSeed, 1 = True)
  ├─ Bytes 5..8:      World Seed (u32, Little-Endian)
  ├─ Byte 9:          Settings Count (u8)
  ├─ Bytes 10..N-4:   Serialized Setting Records:
  │                    ├─ Setting Hash: u16 (Little-Endian)
  │                    ├─ Type Tag: u8
  │                    │    ├─ Tag 0: Signed Varint (Protobuf VLQ + ZigZag: (n >> 1) ^ -(n & 1))
  │                    │    ├─ Tag 1: IEEE 754 32-bit Float (4 bytes, Little-Endian)
  │                    │    └─ Tag 2/3: Fixed Int / Enum / String index
  │                    └─ Encoded Value
  └─ Bytes N-3..N:    Checksum: IEEE 802.3 CRC32 (u32, Little-Endian)
                       Computed over Bytes 0..(N-4) identically to zlib.crc32.
```

### JSON Preset Fallback
The mod also reads and writes standard JSON preset files located in the user's Satisfactory installation under:
`FactoryGame/Configs/RandomWorldGenerator/Presets/<Slot> <Name>.json`

## 3. Scope & Architectural Boundaries

### Clean-Room / Legal Constraints
> **CRITICAL:** Do NOT attempt to bundle or extract proprietary Satisfactory landscape mesh/heightmap files (`BaseMap7`, `holes.u8.pwz`, etc.) into this web application. The mod author confirmed that derived game tile data must not be redistributed outside the game. 

Visual terrain rendering is handled in two legitimate ways:
1. **Pre-Game Visuals:** The player pastes the generated `PW3-` code into Satisfactory's New Game menu, where the mod's native C++ engine (`UPWWorldPreviewWidget`) instantly renders the exact 2D map preview.
2. **In-Game Playthrough:** Once the game starts, our existing Save Viewer tab reads the locally generated `.sav` file and provides the interactive Leaflet map.

## 4. Key Milestones for the Implementing Agent

### Milestone 1: Rust Codec Module (`src/pw_codec.rs`)
Implement the binary parser and serializer:
- `decode_pw3_code(code: &str) -> Result<WorldConfig>`:
  - Validates `PW3-` prefix.
  - Decodes URL-Safe Base64 (padding automatically).
  - Verifies trailing CRC-32 checksum against `crc32fast::Hasher` or `flate2::Crc`.
  - Extracts seed, flags, and deserializes known setting hashes into a structured Rust struct `WorldConfig`.
- `encode_pw3_code(config: &WorldConfig) -> Result<String>`:
  - Serializes `WorldConfig` into the binary byte stream.
  - Appends computed CRC32 checksum.
  - Encodes to URL-safe Base64 and prefixes with `PW3-`.

### Milestone 2: Mathematical Census Engine (`src/census.rs`)
Calculates estimated world resources based on the vanilla 29.3 km² baseline:
- `estimate_census(config: &WorldConfig) -> CensusSummary`
- Baseline counts at 1x:
  - Iron: 127 (39 impure, 42 normal, 46 pure)
  - Copper: 55 (13 impure, 29 normal, 13 pure)
  - Limestone: 94 (15 impure, 50 normal, 29 pure)
  - Coal: 62 (15 impure, 31 normal, 16 pure)
  - Crude Oil: 30 (10 impure, 12 normal, 8 pure)
  - Caterium: 17, Quartz: 17, Sulfur: 16, Bauxite: 17, SAM: 19, Uranium: 5
  - Geysers: 31, Resource Wells: 17 (118 satellites)
- Multipliers:
  - Global `SolidNodeAmount` × per-resource multipliers (0x, 0.25x, 0.5x, 1x, 1.5x, 2x, 3x, 25x, 50x).
  - Purity shifts (`MostlyPure` shifts tiers up, `AllPure` converts all to pure, etc.).

### Milestone 3: Axum REST Endpoints (`src/server.rs`)
Expose API endpoints on the local Axum server:
- `POST /api/architect/decode`: Takes `{ "code": "PW3-..." }`, returns `WorldConfig` + `CensusSummary`.
- `POST /api/architect/encode`: Takes `WorldConfig`, returns `{ "code": "PW3-...", "preset_json": {...} }`.
- `GET /api/architect/defaults`: Returns default values and enum choices for all mod sliders.

### Milestone 4: Dual-Mode Frontend UI (`src/static/index.html`)
Refactor the single-page application into two top-level views:
1. **Header Toggle / Tabs:**
   - 🗺️ **Active Save Map** (existing Leaflet viewer)
   - 🎲 **World Architect & Code Studio** (new interactive tool)
2. **Architect Controls View:**
   - **Seed Input:** Number input with a "Randomize 🎲" button.
   - **Land Layout:** Dropdown for Single Continent, Varied Landmasses, Archipelago, Inland Sea.
   - **Resource Sliders:** Global Solid Node multiplier, per-resource overrides, and cluster spacing/frequency controls.
   - **Purity Selector:** Default, Mostly Pure, Mostly Impure, All Pure, Random.
   - **Interactive Code Box:**
     - Displays generated `PW3-...` string with one-click "📋 Copy Code" button.
     - "📥 Paste Code" modal that populates all sliders from an existing code string.
     - "💾 Save Preset JSON" button to download or write directly to Satisfactory config.
   - **Live Census Card:** Live KPI cards showing estimated total nodes, purity breakdown charts, and wells/geysers.
